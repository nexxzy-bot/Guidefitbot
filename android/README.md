# GuideFit — Android-обёртка для RuStore

WebView-обёртка приложения (без Gradle — сборка через aapt/javac/d8/apksigner).

## Требования

- JDK 17 (`sudo apt install openjdk-17-jdk-headless`)
- Android SDK: `$ANDROID_HOME/platforms/android-35` и `$ANDROID_HOME/build-tools/35.0.0`
  (устанавливаются через `cmdline-tools/bin/sdkmanager "platforms;android-35" "build-tools;35.0.0"`)

## Сборка

```bash
node scripts/gen-icons.js           # пересобрать иконки (после правки scripts/gen-icons.js)
bash android/build.sh               # версия берётся из package.json
bash android/build.sh 2.3.1 231     # явные versionName и versionCode
```

Результат: `android/GuideFit-v<версия>.apk` — подписанный release-APK.

### Ключ подписи

При первой сборке создаётся `android/guidefit-release.keystore` (пароль по умолчанию
`guidefit2026`, меняется переменной `GUIDEFIT_KS_PASS`). **Обязательно сохрани keystore
в надёжном месте** — без него RuStore не примет обновления приложения (подпись должна
совпадать между версиями). Ключ не коммитится в git (см. `.gitignore`).

## Манифест и версии

- `versionName` синхронизирован с `package.json` (сейчас 2.7.2)
- `versionCode` считается из версии: major*100 + minor*10 + patch (2.7.2 → 272)
- при каждой публикации в RuStore повышай versionCode
- `targetSdk 35` (актуальное требование магазина для новых версий), `minSdk 24`

## Что внутри

- `MainActivity` — WebView с localStorage, cookies первого пользователя, только HTTPS
  (`network_security_config`), запрет смешанного контента, Safe Browsing.
- Внутри WebView остаются: домен приложения и VK/OK-домены (вход VK ID).
  Остальные ссылки открываются в браузере.
- Кнопка «Назад» работает внутри истории WebView.
- **Локальные напоминания (v32):** веб-слой передаёт расписание в `ReminderScheduler`
  через мост `window.GuideFitNative`; `AlarmManager` показывает ежедневные уведомления,
  `BootReceiver` восстанавливает расписание после перезагрузки. Время считается по
  выбранному пользователем часовому поясу. Данные никуда не отправляются.
- **Уведомление об обновлении (требование RuStore):** проверка `GET /api/app-version`
  раз в 6 часов; при новой версии — диалог «Обновить в RuStore». Принудительное
  обновление включается в `.env` сервера: `MIN_VERSION=x.y.z`, `FORCE_UPDATE=1`.
- Иконки — все плотности (48–192px) **с полностью залитым фоном** (без прозрачности —
  требование RuStore), генерируются `scripts/gen-icons.js` из SVG.
- `android/ic-store-512.png` — иконка 512×512, RGB **без alpha-канала** (`.flatten()`), для карточки в консоли RuStore.
- **Внешние ссылки (`tgOpenLink`)** уходят в системный браузер через мост
  `GuideFitNative.openExternal`. Раньше `shouldOverrideUrlLoading` возвращал `true`
  без обработки, и внешние ссылки просто не открывались.
- **Выгрузка данных (152-ФЗ, «Скачать копию данных»)** тоже идёт в браузер: в WebView
  файл не скачивается без `DownloadListener`, а браузер сохраняет его по
  `Content-Disposition` — без разрешений на доступ к файлам.
- **Домены проверяются по разобранному host**, а не по подстроке: раньше
  `https://evil.com/#://app.<наш-домен>` считался «своим» и открывался внутри WebView,
  а мост `addJavascriptInterface` доступен любой загруженной странице.
- **Сбой на старте** (нет сети / сервер недоступен) показывает экран с кнопкой «Повторить»
  вместо пустого экрана: `initApp()` вызывается с `.catch(showBootError)`.

## Скриншоты для карточки (снимать вручную)

Макеты RuStore не принимает — нужен реальный интерфейс, поэтому кадры снимаются
с живого аккаунта на телефоне. Требования магазина:

- минимум **3** скриншота для телефона; пропорции **9:16** (до 2160×3840, ≤ 3 МБ);
- ориентация всей ленты определяется по **первому** изображению — держите все вертикально;
- текст на скриншотах — русский, без кликбейта («лучший», «№1») и без рекламы сервисов;
- только реальный интерфейс: не заставки, не экран входа, не заглушки;
- **без элементов интерфейса Android и других приложений** — обрежьте статус-бар (часы,
  батарею) и навигационную полосу снизу: их наличие модерация может счесть нарушением;
- одна тема на все кадры (не смешивайте светлую и тёмную).

Подготовка: наполните аккаунт данными за 5–7 дней — приёмы пищи с фотографиями,
вода, вес, 2–3 тренировки. Пустые кольца и графики на витрине выглядят плохо.
Имя в шапке попадает в кадр — ставьте обезличенное («Пользователь»).

Порядок кадров (он же порядок на витрине; первые три видны в поиске):

1. **Главная** — кольцо калорий, КБЖУ, вода: основная ценность видна сразу.
2. **Питание** — дневник за день со списком блюд и их фотографиями.
3. **Тренировки** — программа или список упражнений с анимацией.
4. **Прогресс** — графики веса и калорий за неделю.
5. **Профиль** — достижения или уровень подготовки.

## Главный риск модерации

Приложение — WebView-обёртка, а правила RuStore отдельно оговаривают, что не
приветствуются приложения, «единственной целью которых является перенаправление на
сайт». Поэтому в комментарии для модератора важно показать, что продукт
самодостаточен: нативный сплэш и экран «нет подключения», нативные напоминания через
`AlarmManager`, нативный диалог обновления, работа без сторонних сервисов.
Смягчает риск и офлайн-оболочка: `static/sw.js` кэширует страницу и шрифты, поэтому
приложение открывается и без сети (показывая экран с кнопкой «Повторить»).

## Известные ограничения WebView-обёртки

- Уведомления — локальные (AlarmManager, ≤2 в день). Серверный пуш (FCM/RuStore Push)
  не подключён сознательно: он потребовал бы хранить токены устройств и держать внешний
  сервис доставки, а локальные напоминания работают без интернета и без передачи данных.
- Сессия хранится в localStorage WebView — при очистке данных приложения потребуется
  повторный вход (для VK-аккаунтов — вход в один тап).
